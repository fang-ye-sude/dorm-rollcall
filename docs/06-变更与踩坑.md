## 二、2026-11-02 审计要点（谁改了什么）

### 填表流水线（pipeline_ops / auto_fill）

- 回读比对 `norm(None)` 曾把空值当字符串 `None` → 每次都判"不符"、整晚不写；改 `""`。
- `fill_weekend` 清残行比目标区间少一行，且 `weekend_rows=[]` 被当缺数据 → 上周名单留在表里；改按真实行数写、`[]` 清空、`None` 才跳过。
- `selfcheck` 只按星期推块，调休必停表 → 优先认 `plan["block"]`。
- 21:40 / 23:50 / 手动三路可能并发 → 加 `flock`；发布与体温也各加锁。
- 失败也 `exit 0`，`/write-now` 据此误判成功 → 改为失败 `exit 1`。
- 月表缺失直接跳过 → 改为**克隆最近月表自愈**。
- 备份硬编码周末表 `s5`、只打 `data/` → 动态查 sheetId，纳入体温主档/名册/脚本，失败告警。
- 周五/周六跑发布 `KeyError` → 中文 `ValueError` + 失败通知。
- `chr(64+c)` 遇列 >26 会写出 `[` → `get_column_letter`。

### 一体机（rollcall_suite）

- `/api/ack` 的 date 未校验 → 可 `../` 挪任意 json；改只认 `YYYY-MM-DD`。
- 配置与信箱写入无锁、固定 `.tmp` → 并发截断成坏 JSON；改 `mkstemp+replace` + `RLock`。
- `/upload` 把 JSON body 当 query 解析，token 只比首字符 → 改双通道 + `compare_digest`。
- `Content-Length` 负数会阻塞、超大静默变 `{}` → 400/413 并排空。
- `/write-now` 连点并发写表 → `FILL_LOCK` 单飞，busy 回 `skipped`。
- 半成品 `.json.gz.tmp` 被当记录 → 只收 `.json/.json.gz`。
- 同日多份件乱序完成会覆盖新计划 → 写前比对 mtime。

### 控制台（webapp）

- 口令用子串匹配 + `?k` 留在地址栏 → 改 cookie 精确匹配、种完 302、加 HttpOnly/Referrer-Policy。
- POST 不校验 Content-Type → 可被跨站表单利用；改非 JSON 一律 415。
- `/static`、`/mark`、`/raw` 路径只做浅正则 → `..` 能探目录；改白名单 + `realpath` 前缀。
- 预览缓存只按 node 做 key、永不过期 → 改 kind+node、120s、上限 12 条。
- 表名/人名进 innerHTML 可注入 → 全量 `esc()` + `data-i` 绑定。
- 节点元数据瞬时失败缓存 120s → 失败 20s；名字取不到时保留上次显示。
- 默认日期用 `toISOString()`（UTC）→ 改本地日期。

## 三、坑录（按症状查）

| 症状 | 根因 | 解 |
| --- | --- | --- |
| 表里一片 `#VALUE!` | 公式 `=A+B` 撞上文字占位 ` - ` | 改 `SUM(...)`，模板已统一 |
| 表里出现文字 `None` | `str(None)` 写进单元格 | 写前转 `""` |
| 填表总说"主表回读不符" | 同上，比对时把 None 当 "None" | `norm(None)=""` |
| 整晚没写表、也没销账 | 体温表查无此人直接抛错 | 已改跳过并记"缺 N 人" |
| 体温表整列空白 | 当月 sheet 不存在 | 自愈：克隆最近月表 |
| 同一张表填了两遍 | 定时与手动并发 | 文件锁 + `/write-now` 单飞 |
| 计划被旧件覆盖 | 同一天多份件乱序到达 | 比 mtime，旧件跳过 |
| 表名忽然空白 | dws 元数据超时，失败缓存 | 失败 20s + 前端保留旧名 |
| 周次差一天 | JS `getDay()+6)%7` 把周一算成周日 | `off = getDay()` |
| 发布把自己在役表撤了 | 重复发同周 | 同周在役红色警告 |
| Safari 打不开预览 | 用了 `inset` 简写 / 全局 `pre{max-height}` | 四边定位；样式只约束 `#log` |
| 桌面 Safari 没有月份控件 | 不支持 `input[type=month]` | 自动退化文本框 `YYYY-MM` |
| 合并单元格写不进去 | 整段写撞合并 | 拆单格；必须整段时 unmerge→写→merge |
| 表格库翻不动 | 自绘表格只读 40 行 | 换 x-spreadsheet（本地化，不靠 CDN） |
| 预览很慢 | 每块各读一次（10 次 dws） | 整表一次读 + 180s 缓存 |
| 家长说链接打不开 | 旧表已撤权 | 「表指向」确认 node，重发权限 |

## 2026-11-04 写表与网络层提速

**写表（pipeline_ops.py）**
- 各层计划并行写：`ThreadPoolExecutor(max_workers=3)`，一层出错不影响别层；
- 周末表 sheet 列表进程内缓存（同一 weekend_node 只查一次，省 1 次 dws/层）；
- dws 重试 3 次、退避 0.6s/1.2s（读与写都可重入，重试安全）；
- 每层日志带 `用时X.Xs`，便于持续观察。

**服务端（rollcall_suite.py）**
- `protocol_version = "HTTP/1.1"` 长连接，客户端复用 TCP；
- JSON 响应 ≥800B 自动 gzip（名册 4825B → 1126B，-77%）；
- 带 ETag，客户端 `If-None-Match` 命中返回 304（0 字节）。

**客户端（Android）**
- 桥接请求 15s 超时 + 3 次重试（500ms/800ms 退避），5xx 与网络错误都会重试；
- 复刻 JS 用 Node 验过：首次失败 → 重试成功。

**实测**
- 单层 `fill_main` 1.86s（3 次 dws ≈ 0.6s/次）；
- 两条计划干跑 1.03s（串行约 1.7s）；
- 名册 gzip 后 -77%，重复请求 304。

**注意**
- 并发上限 3 是为避开接口限流，不是越多越好；
- 长连接与 gzip 对 iPad/安卓都透明，客户端无需升级即可吃到。

## 2026-11-04 iOS 真 OTA（Ad Hoc）

- 前提：付费团队 + 开发者后台同意最新 PLA；
- 工具链：`xcodegen` 由 `project.yml` 生成工程 → `xcodebuild archive` → 导出 ad-hoc → 上传 IPA 与 manifest；
- 一键脚本：`./build-ios-adhoc.sh`（归档 + 导出 + 提示发布路径）；
- 版本号**必须写在 `project.yml` 的 `info.properties`**（xcodegen 会覆盖 `DormRoll/Info.plist`）；
- 部署目标 iOS 17（代码用了 `ContentUnavailableView`）；
- 分发地址：`/api/app/latest-ios`、`/api/app/ios/DormRoll-<版本>.ipa`、`manifest.plist`；
- Ad Hoc 只能装描述文件内设备（现 4 台），新设备要先加 UDID 再导出。
