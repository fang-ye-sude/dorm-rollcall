## 二、缘起

原来每晚手抄三张表：请假汇总（五天一块）、周末未返校、宿舍体温。一人念、一人抄、一人核，二十分钟起，还常串行——张三的事假写进病假列，某房漏一个人，小计对不上。周五要把一周的表归拢，月底还要重做体温表。

问题不在人慢，在**同一条信息被抄了三遍**。点名时其实已经知道"谁、哪房、什么假"，后面全是搬运。项目要做的只是把这次搬运交给机器。

## 三、目标与非目标

**目标**

1. 点名一次，三表自动落数，人工只做核对。
2. 周表每周自动出新、旧表自动撤，家长链接始终有效。
3. 任一天可回溯：谁点的、传的什么、写了哪几格、几时写的。
4. 断网可点，联网补传，不因网络丢一晚数据。
5. 学校原表版式不变，打印、盖章、贴墙照旧。

**非目标**

- 不做学生端、家长端 App；家长只看链接。
- 不做人脸、扫码、GPS 点名。
- 不判断请假真伪；四维由宿管老师点。
- 不接管钉钉账号体系，仅用共享表与群。

## 七、验收标准

1. 一晚从上传到三表更新 ≤ 2 分钟（不含人点的时间）。
2. 三表数字与点名件逐人可对：应到 78、实到、请假 N。
3. 断网、重复上传、连点填表、定时与手动并发，四种情况都不产生脏数据。
4. 周日发布后家长能打开空表，旧表链接失效。
5. 备份能在另一台机器还原出同样的表与数据。

## 八、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 钉钉表格 API 抖动 | 填表失败 | 计划留信箱 + 23:50 补扫 + 失败告警 |
| dws 登录态过期 | 全线停 | 每两小时保活；过期即告警重登 |
| 名册与表不一致 | 某人写不进去 | 别名表 + 缺人跳过记日志 + 事后补行 |
| 表被误撤 | 家长打不开 | 发布前同周在役警告；旧表改名不删 |
| 单机故障 | 服务不可用 | 全部数据可打包迁移；代码与文档同库 |
| 口令外泄 | 控制台被改 | 口令文件 600、不进日志、`?k` 用完即清 |
