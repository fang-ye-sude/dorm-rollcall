# 03 · 实现方法

## 一、总体架构

```
 iPad「B座点名」                应用容器  app-container (192.168.1.20)
 ┌───────────────┐   upload    ┌─────────────────────────────────────┐
 │ WKWebView     │ ──────────▶ │ rollcall_suite.py  :8100            │

 │ 本地存储      │ ◀────────── │  data/marked  data/pending          │
 └───────────────┘   回执      └──────────┬──────────────────────────┘
                                          │ 取计划
                                          ▼
                              ┌──────────────────────────────┐
                              │ ops/pipeline_ops.py          │
                              │  fill / publish / sweep /    │
                              │  tempmonth / backup          │
                              └──────────┬───────────────────┘
        dws CLI（钉钉表格 API）           │
        ┌───────────────┬────────────────┼───────────────┐
        ▼               ▼                ▼               ▼
   主表 node      周末表 node       体温表 node      本地体温主档
                                                        xlsx
                    ▲
                    │ 控制台（rc-web :8120）
        ┌───────────┴────────────┐
        │ webapp.py 单文件       │
        │ 今日一线/发布/计划/表指向│
        │ 定时/表格库/原始件/日志 │
        └────────────────────────┘
```

三条铁律：

1. **原样留档**：上传件（`.json.gz`）永不删、不改，只作"证据"。
2. **信箱单一**：`data/pending/<date>.json` 一天只留一份，同日再传覆盖（以最新为准）。
3. **销账才走**：主表写成功才 `ack`；失败留信箱等补扫。

## 二、三张表的结构与写入位

### 请假汇总表（在线共享表，sheet `s1`）

```
行 1  ┌ 标题 ─────────────────────────────┐
行 3  │ 宿管办批假 | 部系批假 | …          │  ← I~L 列是名单
行 4  │ 大专 | 事假 病假 事假 病假         │
行 5  │ 103 房 学生1 …                    │  ← 日期行在 head+3，数据行在 head+14
 …    │ 8 行学生                         │
行 20 │ 小计 / 合计 / 总计                │
行 25 └ 下一块（B座二层）…                ┘
```

五块 head = **1, 25, 49, 73, 97**；对应日期行 4/28/52/76/100，数据行 **15/39/63/87/111**。

写入位：`C..L`（应到中专/大专、实到中专/大专、请假中专/大专、宿管办名单、部系名单）。

### 周末未返校统计（在线表，sheet 名 `B1`）

`B2:D51`，逐行 姓名 | 房号 | 班级；不足 50 行时余下清空。sheetId 不写死，按标题 `B1` 动态查。

### 宿舍点体温（本地 `app/data/宿舍点体温.xlsx` + 在线共享表）

- 每月一个 sheet，名 `YYYY.MM`；日列 C 起，只排**周日~周四**。
- 每房一块 8 行：`A 列房号（合并）| B 姓名 | C..Y 日值`。
- 在校生日值 = `=ROUND(RAND()*(37-36.3)+36.3,1)`；请假写 `事` / `病`。
- 写完本地再**逐格**同步到在线表（整段写会撞合并单元格）。

## 三、核心算法

### 1. 日期 → 块号

```python
周日=块0, 周一=1, 周二=2, 周三=3, 周四=4
block = config.blockmap.get(date)  # 调休/补班可显式指定
        或 按星期推
```
`selfcheck` 会校验"计划里的 block / row / 日期"三者自洽，不认就报错、不写表、不销账。

### 2. 人数与四维

- 应到 = 名册该房人数（宿管名册 `roster_b1f.json`，78 人）
- 实到 = 应到 − 请假数
- 请假按四维分：DS/DB 进"宿管办批假"，XS/XB 进"部系批假"；事/病分列。
- 名单格式：`25电商学生334`（班级简称 + 姓名），同格空格分隔。

### 3. 名字对齐（最容易出错的地方）

同一个人在不同地方可能写法不同：

| 名册 | 表上 | 处理 |
| --- | --- | --- |
| 学生286 | 杨箫 | `name_aliases` 杨箫→学生286 |
| 学生91 | 周师涵 | 周师涵→学生91 |
| 学生450 | 邹李沐岐 / 邹李沭歧 | 统一到 学生450 |

规则：先查别名表，再按"去掉班级后缀、去空白、去不可见字符"归一化比。**体温表查无此人**：跳过并记日志（不炸整条链），新学生可手工补行后再同步。

### 4. 写表的三个坑与对策

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 合并单元格 | 整段写返回业务错误 | 拆成单格写；必须整段时 `unmerge → 写 → merge` |
| `None` 变字符串 | 表里出现文字 `None` | 统一 `"" if v is None else str(v)` |
| 文字占位参与运算 | `#VALUE!` | 公式一律 `SUM(...)`（SUM 跳过文字） |

### 5. 并发控制

- `pipeline_ops` 用 `/tmp/rc-{fill,publish,tempmonth}.lock` 文件锁，抢不到就退出（不排队）。
- 一体机 `/write-now` 用进程内 `FILL_LOCK` 单飞，连点只跑一次。
- 配置与信箱写入用 `mkstemp + os.replace` 原子落盘，避免半截 JSON。

## 四、数据格式

### 点名件 `data/marked/20261102-153111.json.gz`

```json
{
  "v": 4, "type": "marked", "ref": "roll/20261102-153111.json.gz",
  "d": "2026/11/2 15:31:01", "weekend": false,
  "n": [["学生79 网络", "103", "XS"], ["学生467", "105", "DS"]]
}
```
`n` 每项 = 姓名（可含班级后缀）| 房号 | 四维。

### 计划 `data/pending/2026-11-02.json`

```json
{
  "date": "2026-11-02", "range": "C39:L39", "block": 1, "row": 39,
  "values": [78, "/", 65, "/", 13, "/", "名单…", "/", "/", "…"],
  "weekend": false, "weekendN": 0, "leaveN": 13,
  "students": [{"name":"学生79","room":"103","q":"XS"}, …],
  "marked_file": "marked/20261102-153111.json.gz"
}
```
`values` 就是主表该行要写的 10 个格子（C..L）。


## 六、为什么这么选

- **单文件 webapp**：控制台只在 应用容器 上用，省掉构建链与静态目录；预览用开源 x-spreadsheet（本地化到 `/static`），不依赖外网 CDN。
- **dws CLI 而非 SDK**：钉钉表格 API 鉴权麻烦，CLI 已登录，脚本直接调，出错信息也直观。
- **本地体温主档 + 在线同步**：体温表要保留 RAND 公式与合并格式，openpyxl 改本地最稳；在线只同步数值。
- **信箱式解耦**：上传与填表分离，任一端失败都能重试，不会丢数据。
