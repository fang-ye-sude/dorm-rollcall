# 01 · 需求

## 背景

B 座（男生宿舍一层）每晚上自习前要点名。请假分四类，既要报宿管办，也要报部系：

| 代号 | 含义 | 落到表上 |
| --- | --- | --- |
| DS | 宿管办事假 | 主表 I 列（宿管办批假）· 事 |
| DB | 宿管办病假 | 主表 J 列 · 病 |
| XS | 部系事假 | 主表 K 列（部系批假）· 事 |
| XB | 部系病假 | 主表 L 列 · 病 |

原先靠手抄三张表，一晚二十分钟起，容易漏人、串行。要做的是把"点名"和"三张表"接上。

## 角色与诉求

- **宿管老师**：点得快、不怕断网、点错能改、上传一次就完事，不要学新东西。
- **家长**：一张表看清楚今天谁请假、什么假、哪个班；周末另有一张返校名单。
- **管理者**：周表自动出、链接自动发、能随时抽查、能手动干预、出事能回溯。
- **学校**：表要跟原来格式一模一样，打印、盖章、贴墙都不违和。

## 功能需求

### A. 点名（iPad）

1. 按房间列名单，点人标记缺勤；缺勤再选四维之一。
2. 断网可点，数据存本机；联网后上传。
3. 上传内容含：日期时间、名单（姓名/房号/四维）、是否勾了"生成周末返校统计"。
4. 上传后可一键"立刻填表"，不必等定时任务。
5. 点错能回退：改标记、重新上传，以最新一份为准。

### B. 三张表

| 表 | 结构 | 写什么 |
| --- | --- | --- |
| 请假汇总表 | 一周五天，每天一块；每块 8 行学生 + 小计/男生合计/中专大专/总计 | 当日一行：应到/实到/请假（中专、大专分列）+ 批假名单；合计自动算 |
| 周末未返校统计 | B1 sheet，B2:D51，逐行 | 勾了返校时：名单、房号、班级 |
| 宿舍点体温 | 每月一个 sheet，按房分块 8 行，日列 C..Y（周日–周四） | 当日列：请假写"事/病"，在校保留随机体温公式 |

三张表都以**钉钉在线表格**形式发布，家长用链接看，不需要账号。

### C. 发布

1. 每周日自动发下周两张表，命名带日期区间，例如 `11.08-11.12住宿生请假汇总表`。
2. 旧表撤权、改名"已撤-"，不删除（留档）。
3. 链接发固定联系人；表给群 EDITOR 权限。
4. 也能手动发布，且要能看清"发哪一周、撤哪张、会不会误撤在役表"。

### D. 填表

1. 每晚取当日计划，写主表 + 体温（勾返校则加周末表）。
2. 写成功销账；失败留信箱，23:50 补扫再试。
3. 可试运行（dry-run）：只算不写。
4. 可挑目标表：只写主表、不写体温等。
5. 结果可查：写了几格、跳了谁、失败原因。

### E. 备份与可恢复

1. 每周打包：在线表快照 + 应用容器 数据 + 体温主档 + 名册 + 脚本。
2. 任意一天能查"那天写了什么"（原始件、计划、日志）。

## 非功能需求

- **可靠**：定时任务与手动操作并发不打架；单点失败不影响其它表。
- **可追溯**：原始上传件一律保留，不因销账而删。
- **安全**：控制台需鉴权；一体机接口需 token；路径不可穿越；口令不落日志。
- **兼容**：Safari / iPad Safari 可用；表格式与学校原表一致。
- **零依赖**：服务端只用 Python 标准库 + openpyxl + dws CLI；前端不引外网 CDN。

## 不做什么

- 不做学生端、不做家长端 App（家长只看链接）。
- 不改学校表的版式与公式逻辑（只把公式改成 SUM 形式避免 `#VALUE!`）。
- 不做人脸/扫码点名。
- 不自动判断请假真伪，四维由宿管老师点。

## 验收标准

1. 一晚点名到三表更新 ≤ 2 分钟（不含人点的时间）。
2. 三表数字与点名件一致：应到 78、实到、请假 N 可逐人核对。
3. 断网、重复上传、连点填表、并发定时，四种情况都不产生脏数据。
4. 周日发布后，家长打开链接能看到空表；旧表链接失效。
5. 备份可在另一台机器还原出同样的表与数据。
