# 07 · 工作原理

> 这份讲"为什么它能自己跑对"，不是操作步骤。想动手改代码的，先读这篇。

## 一、三个对象：件、计划、表

整条产线只在这三样东西之间倒手。

```
 件（事实）            计划（意图）                 表（结果）
 iPad 点完的原始记录 →  该日该块要写的十格内容  →  家长看到的三张表
 不可变，永久留档       一天一份，可覆盖          可被重写，幂等
```

- **件**是"发生了什么"，只增不改。
- **计划**是"要写成什么"，由件算出，带自检信息（块号、行号、区间）。
- **表**是"别人看到的"，是计划的投影。

分开的好处：件丢了还能补传；计划错了能重算；表写坏了能重写——三者互不牵连。

## 二、状态机

```
            ┌──────────── 失败：留信箱，23:50 重试 ────────────┐
            ▼                                                │
[已上传] → [入信箱] → [自检] → [写主表] → [写周末表] → [写体温] → [回读校验] → [销账]
                │         │                                                    │
                │         └─ 不自洽：报错不写（宁可不动，不乱写）              │
                └─ 同日多件：以 mtime 最新为准，旧件直接跳过 ─────────────────┘
```

四个不变量：

1. **不销账就等于没成**。任何一步抛错，计划留在信箱，不会悄悄消失。
2. **写前自检**：日期、块号、行号三者必须自洽，否则不写。
3. **写后回读**：读回该行与预期逐格比对，不符也算失败。
4. **销账只认"主表已写"**：只补体温不写主表时，不销账（`--targets` 不含 main）。

## 三、日期模型：一天落在哪一块

主表一周五天，五块：

| 星期 | 周日 | 周一 | 周二 | 周三 | 周四 |
| --- | --- | --- | --- | --- | --- |
| 块号 | 0 | 1 | 2 | 3 | 4 |
| 数据行 | 15 | 39 | 63 | 87 | 111 |

- 周五、周六不点名，无块；误传会被告知"不在周日~周四，仅存档"。
- **调休/补班**：`config.blockmap` 可给某日显式指定块号，例如把某个周六当周一用。
- 跨月：体温表按月分 sheet（`YYYY.MM`），日期取计划里的 `date`，不看运行时刻。
- 23:50 补扫跑的是同一天，若已销账则空箱静默——不会把昨天的表再写一遍。

## 四、写入模型：模板 + 补丁

三张表都不是"从零画"，而是"拿模板，填格子"。

- **主表**：以空白模板为底，只写当日那一行的 C..L 十格（应到、实到、请假分列、两栏名单），其余格（小计、合计、总计）保留模板公式，写完全部交给表格自己算。
- **周末表**：只写 B2:D51，写入行数 = 名单长度，余下清空；名单为空则整片清空（`weekend_rows=[]` 与"缺字段"是两回事）。
- **体温表**：本地 xlsx 保留合并单元格与 RAND 公式，只改当日列表头那一格；写完再把这一列**逐格**同步到在线共享表。

为什么不用整段写：在线表格有合并单元格，整段写会撞上合并区返回业务错误。所以要么拆成单格，要么先 `unmerge → 写 → merge`（主表行 45/47 的合计格就是后者）。

## 五、数字与文字：为什么公式要写成 SUM

学校原表用 `=C39-E39`、`=G41+G43` 这类加法。模板里有些格子是文字占位 ` - ` 或 `/`，加法一碰文字就 `#VALUE!`，而且会顺着引用传染。

对策：所有汇总公式改成 `SUM(...)`。SUM 的语义是"忽略非数字"，正好符合"占位符不算数"的业务含义。这不是美化，是让公式容错。

同理，空值写表时必须转空串：`"" if v is None else str(v)`。否则单元格里会出现文字 `None`，回读比对也会失真（`norm(None)` 已统一按空串处理）。

## 六、并发：三个入口，一把锁

同一条产线可能被三处同时触发：21:40 定时、23:50 补扫、控制台或 iPad 的手动填表。互相踩的后果是重复写、重复销账、体温表读改写交错丢格。

三层防护：

1. **进程锁**：`/tmp/rc-fill.lock`（publish、tempmonth 各有自己的锁）。抢不到不排队，直接退出并记日志。
2. **接口单飞**：一体机 `/write-now` 用进程内锁，连点十次只跑一次，其余回 `skipped:true`。
3. **原子写**：配置与计划用 `mkstemp + os.replace`，不会出现半截 JSON；半成品 `.tmp` 也不会被当成记录读进来。

## 七、一致性与幂等

- **同名件**：同一天多份件，只有 mtime 最新的那份能生成计划；旧件迟到会被跳过并记日志。
- **重复执行**：写表是幂等的（同样输入写同样格子），所以失败重试安全；销账是"移动文件"，重复执行第二次找不到源文件即视为已完成。
- **回读校验**：写完立即读回比对。它挡住的不只是写失败，还有"写到了别的行"这类错位。
- **别名归一**：名册与表上偶有异体字（杨箫/学生286、周师涵/学生91、邹李沐岐/学生450）。比对前先查别名表，再去班级后缀与空白。体温表查无此人只跳过并记"缺 N 人"，不阻断主表与周末表。

## 八、缓存：慢在哪，就在哪加

| 层 | 缓存什么 | 时长 | 失效方式 |
| --- | --- | --- | --- |
| 控制台后端 | 在线表元数据（名/建/改） | 成功 120s，失败 20s | 过期重取；失败不污染 |
| 控制台后端 | 导出 xlsx | 180s | 按表最后修改时间比对 |
| 控制台前端 | 预览文件二进制 | 120s，上限 12 条 | 按 kind+node 作键 |
| 控制台前端 | 表候选列表 | 60s | 过期重取 |

原则：**读多写少的才缓存，写路径一律不缓存**。表格元数据一旦取不到，前端保留上次显示，不让表名闪成空白。

## 九、鉴权与边界

```
浏览器 ── Basic 或 ?k=口令 ──▶ 控制台（cookie HttpOnly，地址栏即时清空）
iPad   ── token ─────────────▶ 一体机 /upload、/list
脚本   ── admin ─────────────▶ /write-now、/api/ack、/api/config
```

- 控制台所有写操作要求 `Content-Type: application/json`，挡跨站表单（CSRF）。
- 静态与下载路径做白名单 + `realpath` 前缀校验，`..` 一律拒绝。
- 一体机只在内网；公网只经 nginx 的 `/dianming/api/`，由宿主机 socat 转进 应用容器。
- 口令与 token 不写日志；`?k=` 种完 cookie 立即 302，避免留在地址栏与 Referer。

## 十、部署拓扑

```
家长浏览器 ──https──▶ 北京轻量 nginx ──WG──▶ 内部服务器 192.168.1.20 ──socat──▶ 应用容器:8100/8120
                                                    │
iPad ──https──▶ example.com/dianming/api/ ───────────┘
                                                    │
                                     dws CLI ──▶ 钉钉表格（三张在线表）
```

应用容器 内部两个服务、五个定时器、一个本地 xlsx 主档。所有状态都在文件里（件、计划、配置、日志），所以迁移只需搬 `/srv/dormroll` 一个目录。

## 十一、失败恢复：每一段都能单独补

| 断在哪 | 现状 | 怎么补 |
| --- | --- | --- |
| 上传前（iPad 断网） | 数据在本机 localStorage | 联网重传，件进信箱 |
| 上传后未填 | 计划在 `pending/` | 控制台点「写入三表并销账」 |
| 写主表失败 | 计划还在，表未动 | 看日志修正后重跑，幂等安全 |
| 写体温失败 | 主表已写，计划未销 | 单跑 `fill --targets=temp`，再手动销账 |
| 销账失败 | 表已写，计划还在 | 重跑会重复写同样格子（无害），或直接 ack |
| 发布失败 | 旧表仍有效 | 重跑发布；旧表在成功后才撤权 |

## 十二、一天的时序

```
21:31  iPad 上传件 ──▶ 一体机落 data/marked，算计划入 pending
21:31  iPad 点「立刻填表」 ──▶ /write-now（单飞）──▶ fill
21:32  fill：自检 → 写主表 → 写周末表（若勾）→ 写体温 → 回读 → ack
21:32  控制台「今日一线」三格转绿，最近记录多一行"销账 2026-11-02"
21:40  定时 rc-fill 再跑一次：信箱空 → 记"当日已填过·静默"，不重复写
23:50  rc-sweep：仍空 → 静默；若当晚漏传而 21:40 后补了件 → 这时写入
```

## 十三、设计取舍

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| 信箱解耦上传与填表 | 任一端挂了都能重试，不丢数据 | 多一份文件要管 |
| 在线表只当"投影" | 表格可重建，真相在件与计划 | 在线表不能直接手改成"真相" |
| 本地体温主档 + 在线同步 | 保住公式与合并格式 | 同步要逐格，慢一点 |
| 控制台单文件 | 免构建、免静态目录、改完即生效 | 文件大，前端改动需 `node --check` |
| 不用数据库 | 单人宿舍场景，文件足够且可打包 | 并发靠锁，不适合多人高频写 |
